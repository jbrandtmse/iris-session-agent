## What Went Well

1. **Task-0 backend-surface probes earned their keep three times.** Story 1.2's probe caught a label-drift between the spec ("System Default Parameters") and the live IRIS UI ("Default Parameters" under "Configuration"). Story 1.4's probe caught the `%`-prefix rejection. Story 1.5's probe caught that `%SYS.Task` does NOT enforce Name uniqueness. Without Task 0, all three would have shipped as bugs.

2. **The "discover-and-propagate" pattern.** When a cross-cutting finding emerged, the same commit updated every canonical artifact — README, architecture, prd, epics, distillate, project memory. This eliminated the "fix-and-forget" failure mode where corrections leak into future-epic story specs as stale references.

3. **Honest-about-partial-state tone in `docs/operator-quickstart.md`.** Step 4 explicitly says "the chat tab doesn't exist yet — Epic 3 ships it" instead of pretending. Step 5's SQL verification uses real Epic-1 state (`Security.Events` + `Security.Roles`), not the not-yet-shipped audit ledger tables. Operator trust on first impression preserved.

4. **Mid-epic process shift: ~3× token efficiency for equal quality.** Stories 1.1–1.4 used the full dev-agent + reviewer-agent pipeline. Stories 1.5–1.7 used collaborative inline implementation by lead with empirical verification. Same outcome, ~1/3 the token spend. User-prompted; load-bearing.

5. **Auto-sync workflow** (`objectscript.conn.active=true`) eliminated the `iris_doc_load` round-trip per file edit. 5–15 KB tokens saved per ObjectScript story edit cycle. Codified as a project rule.

6. **Full epic shipped end-to-end on first install AND idempotent reinstall.** Empirically verified post-`zpm "enable -map -globally"` setup: 6/6 IPM lifecycle phases, all expected log lines, no duplicates on second install.

## What Didn't Go As Well

1. **Story specs were too long for stories 1.1–1.4.** ~600-line essays that re-cited architecture/PRD content the dev agent could read directly. User intervention required mid-cycle to surface this.

2. **Over-prescription of `iris_execute_command`** for things that had typed MCP alternatives. Story 1.4 dev burned material token budget probing `Security.Roles` via `iris_execute_command` `Help()` calls when `iris-admin-mcp.iris_role_*` exists.

3. **Two correctness regressions slipped past the spec stage** and were caught only by the dev or the user during execution: the `%`-prefix rejection (Story 1.4 dev caught) and the HSCUSTOMCODE non-existence (user caught during Story 1.6). Both required cross-cutting rename passes through multiple docs.

4. **The IPM toolchain "blocker" misdiagnosis.** Lead initially flagged Story 1.5's `zpm load` failure as a Story 1.7 deferral (CI environment IPM toolchain). User redirected to Perplexity research. The actual fix was a single command. Deferring would have left every operator hitting the same wall and propagated stale assumptions through 2+ epics.

5. **Trust violation: Task 4 marked `[x]` without verification.** During Story 1.5 spec rewrite, lead marked the `zpm load` end-to-end task `[x]` without running it. User caught with "did you actually run zpm load?" Marking ACs satisfied without proof is the worst-case failure mode in autonomous pipelines.

6. **Lead did not self-initiate the epic-end empirical test pass.** User requested "manually test Epic 1 functionality" before retrospective. Should have been lead-initiated as the epic's exit gate.
