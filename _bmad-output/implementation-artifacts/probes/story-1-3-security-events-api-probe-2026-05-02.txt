----------------------------------------------------------------
Probe 2: Wildcard-Name acceptability — does IRIS treat a literal
"<provider>" string as a wildcard pattern when matching audit
emissions?
----------------------------------------------------------------

Command: Set tSC = ##class(Security.Events).Create("ProbeTest","WildcardTest","<provider>","Probe of wildcard placeholder",1)
         Write "Exists check: ",##class(Security.Events).Exists("ProbeTest","WildcardTest","<provider>"),!

Output:
  Status: (empty -> $$$OK)
  Exists check: 1

The literal string "<provider>" was accepted by Create() as the Name
field. So far so good — no syntactic rejection.

----------------------------------------------------------------
Probe 3: Does an audit call with a literal name (e.g. "openai")
match a registered "<provider>" placeholder triple?
----------------------------------------------------------------

Command: Set ev1 = ##class(Security.Events).Exists("ProbeTest","WildcardTest","openai")
         Write "Exists openai literal vs <provider> reg: ",ev1,!
         Set tAudit = $System.Security.Audit("ProbeTest","WildcardTest","openai","probe test","probe data")
         Write "Audit return for unmatched literal name: ",tAudit,!

Output:
  Exists openai literal vs <provider> reg: 0
  Audit return for unmatched literal name: 0

DEFINITIVE RESULT: IRIS does NOT treat "<provider>" as a wildcard.
With only the placeholder registered, an audit emission of literal
"openai" returns 0 — the silent-failure pattern the project rule
warns about.

DECISION (recorded in story Task 0 Output)
----------------------------------------------------------------

Signature:                    Create(Source, Type, Name, Description, Enabled, Flags) As %Status
Wildcard Name acceptable?:    NO (literal placeholder strings register but do not match audit emissions)
Chosen registration approach: Approach 1 — literal names per provider/enum/task.
                              ToolCall is deferred to lazy registration in Epic 2+ because the
                              tool name universe is not known at Story 1.3 install time.

Concrete triples registered by EnsureEvents():

ToolCall: deferred to lazy registration in Epic 2+ (Story 2.10's tool registry
boundary is the natural place to register tool-specific event names on first
