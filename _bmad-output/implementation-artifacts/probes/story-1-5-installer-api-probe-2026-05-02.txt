PROBE 2: %SYS.Task — canonical creation shape
================================================================================

Command (switch into %SYS, create a probe task, save):
    Set tNS = $NAMESPACE
    Set $NAMESPACE = "%SYS"
    Set tTask = ##class(%SYS.Task).%New()
    Set tTask.Name = "TEST_PROBE_TASK_DELETE_ME"
    Set tTask.NameSpace = tNS              ; HSCUSTOM
    Set tTask.TaskClass = "SessionAgent.Audit.Emit"
    Set tTask.TimePeriod = 0               ; DAILY
    Set tTask.DailyFrequency = 0           ; ONCE per day
    Set tTask.DailyStartTime = 7200        ; 02:00:00 in $H seconds-since-midnight
    Set tSC = tTask.%Save()
    Write "Save status: ",$System.Status.GetErrorText(tSC),!
    Write "ID: ",tTask.%Id(),!

Output:
    Save status:
    ID: 1004

(Empty status text = $$$OK; a numeric ID was assigned.)

%SYS.Task properties exposed for scheduling (via %Dictionary.CompiledClass):
    Name (%String)             — task name (NOT unique on its own; see Probe 3)
    NameSpace (%String)         — namespace where the task is run
    TaskClass (%String)         — full class name implementing the task body
    TimePeriod (%Integer)       — 0 DAILY, 1 WEEKLY, 2 MONTHLY, 3 MONTHLYSPECIAL, 4 RUNAFTER, 5 ONDEMAND
    TimePeriodEvery             — every-X interval governed by TimePeriod
    TimePeriodDay               — day-mask governed by TimePeriod
    DailyFrequency (%Integer)   — 0 ONCE-per-day, 1 SEVERAL-per-day
    DailyStartTime (%Time)      — seconds-since-midnight ($H format) for first run
    DailyEndTime, DailyIncrement, DailyFrequencyTime — only used when DailyFrequency=1

For SessionAgent's three sweep tasks the canonical shape is:
    PurgeOrphanedChatHistory: TimePeriod=0 DAILY, every 1 day, DailyStartTime=7200 (02:00)
    PurgeStaleSearchChat:     TimePeriod=0 DAILY, every 1 day, DailyStartTime=10800 (03:00)
    UserVocabularyDecay:      TimePeriod=1 WEEKLY, every 1 week, TimePeriodDay=1 (Sunday), DailyStartTime=14400 (04:00)

================================================================================
PROBE 3: %SYS.Task DEDUP STRATEGY — *no* built-in Exists check
================================================================================

Hypothesis: rerun the same Save with the same Name to see if the framework
rejects duplicates. (If it errored on duplicate, dedup could be try/catch.)

Command:
    [save same probe task again with the same Name]

Output:
    Duplicate ID: 1005

VERDICT: %SYS.Task does NOT enforce uniqueness on Name. A naive re-save with
the same Name produces a SECOND row with a different ID.

Verified via SQL:
    SELECT ID, Name FROM %SYS.Task WHERE Name = ?  -- 'TEST_PROBE_TASK_DELETE_ME'
    Row: ID=1004 Name=TEST_PROBE_TASK_DELETE_ME
    Row: ID=1005 Name=TEST_PROBE_TASK_DELETE_ME

CONSEQUENCE: `ScheduleTaskIfClassExists` MUST do an explicit existence check
BEFORE calling %Save(). The chosen pattern is:

    Set tFound = 0
    &sql(SELECT ID INTO :tID FROM %SYS.Task WHERE Name = :pTaskName)
    If SQLCODE = 0 { Set tFound = 1 }   ; row found, skip insert
    If 'tFound {
        Set tTask = ##class(%SYS.Task).%New()
        Set tTask.Name = pTaskName
        ; ... set NameSpace, TaskClass, TimePeriod, DailyFrequency, DailyStartTime ...
        Set tSC = tTask.%Save()
    }

Both probe tasks (ID 1004, 1005) were cleanly deleted via %DeleteId. SQL
confirmed zero remaining rows with Name = 'TEST_PROBE_TASK_DELETE_ME'.
