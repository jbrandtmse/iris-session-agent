## Significant discoveries

**One — Mock matrix and live-test classes catch different bug shapes than chat-panel manual-test does.**

The 52-pair mock matrix (Story 5.4) and 4 `*ProviderLive` classes are both *API-level* surfaces: bare canonical inputs, ProviderOverride queue (mocks) or direct provider invocation (live). Bugs 1, 2, 3 require the *operator-storage path* (SQL `UPDATE Config.Agent SET EndpointUrl = ...`) AND the *runtime tool registry* (13 tools assembled at startup, not hand-built fixtures) to manifest. The chat panel goes through both paths; the existing test surfaces don't.

**Disposition (per Project Lead 2026-05-06):** user-led chat-panel manual-test is the canonical catch surface for this bug shape and the project explicitly accepts the human-in-the-loop step at epic-end. Codified as AI-1 below — a sub-clause to Rule 6 sharpened battery for any epic that touches LLM/provider code.

**Two — Retry-loop duplication is now at 1.7× the deferred threshold (202 lines across 4 providers).**

Story 2.9 set the deferred threshold at ~120 lines. Story 5.4 dev's audit (Completion Notes line 327-337) measured 202 lines of structurally-identical retry orchestration across `OpenAIProvider`, `AnthropicProvider`, `GeminiProvider`, `OpenAICompatProvider`. Refactor to `RetryWithBackoff.ExecuteOnInstance(pProviderName, pCallback)` is now strongly justified.

**Three — `$Char(0)` sentinel is a cross-codebase pattern, not a `Tool.Inspection`-only quirk.**

Story 4.0 codified inline normalization in 2 sites (`GetMessageBody`, `GetMessageDetail`). Bug-1 showed 6 more sites needed the same treatment in the LLM provider stack. The codification needs to be elevated from "inline pattern at site of use" to a *grep target* — any time a `Config.Agent.*` field is read, the read site needs `$Char(0)` normalization.
