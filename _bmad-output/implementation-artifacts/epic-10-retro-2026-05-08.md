## Significant discoveries

**One — User-driven Chrome-DevTools walkthroughs are the single most valuable verification surface for UI epics.** Across 3 walkthroughs, 5 operator-blocking defects surfaced (F-1 release-blocker; F-2 release-blocker; F-3 + F-4 + F-5 UX-impact). ZERO of them were caught by 423 unit tests, by code-reviewer probes, or by alternate-form evidence. Rule 12's "layout-correctness requires screenshot OR DOM probe" was insufficient because runtime behavior (event listener bindings, hyperevent dispatch, refresh callbacks) requires real-browser execution. AI-1 + AI-4 codify this lesson.

**Two — Auto-memory feedback entries scale across cycles when written from real incidents.** Two memory entries written mid-Epic-10 (`feedback_no_real_api_keys_in_tests.md` + `feedback_use_config_screens_not_sql.md`) are durable rules that apply to all future cycles. The pattern works: (a) real incident occurs; (b) lesson articulated as rule with **Why** + **How to apply**; (c) saved with cross-references to originating incident. Both rules are now load-bearing for future stories.

**Three — Hotfix-driven cycles produce real defect-finding value when verification rigor is maintained.** Stories 10.10 / 10.11 / 10.12 / 10.13 each surfaced a genuine empirical issue that no upfront planning could have predicted (Zen lifecycle, secret-scanning revocation, parent class hidden behavior, form-cascade gap). 4 hotfixes is unusual for a single epic but each was justified. The pattern works because the walkthroughs that surfaced findings ALSO drove re-verification of the fixes — the cycle has a self-correcting property when walkthrough cadence is maintained.

**Four — FR59 LIVE-mode 92/92 is achievable but requires multiple runs per cycle.** Across 4 FR59 runs, the failure modes were: (run 1) credential revocation by upstream provider, (run 2) deterministic LLM-side fixture-format heuristic, (run 3) transient provider mid-flight failure, (run 4) clean. Each run cost ~$0.05–$0.15 and ~5 minutes. The 92/92 gate is achievable but plan for 2–4 runs per release cycle.
